# Como contribuir

## Contexto do projeto

O Meu Study Hub TI é um repositório acadêmico individual. A proprietária mantém as decisões de organização, os conteúdos e a publicação final. Sugestões são bem-vindas, mas alterações só devem ser incorporadas após revisão da proprietária.

## Sugestões e correções

Para sugerir uma melhoria:

1. Verifique se a sugestão já não está contemplada na documentação.
2. Descreva o objetivo de forma clara, informando quais arquivos ou links seriam afetados.
3. Não envie dados pessoais sensíveis, credenciais, tokens ou chaves de API.

Em caso de vulnerabilidade, siga as instruções de [SECURITY.md](SECURITY.md) em vez de abrir uma issue pública com detalhes sensíveis.

## Padrão para alterações futuras

Caso seja autorizado a colaborar:

1. Crie uma branch com nome descritivo, por exemplo `docs/melhora-readme` ou `fix/corrige-link-pages`.
2. Faça alterações pequenas e relacionadas a um único objetivo.
3. Revise links, ortografia e caminhos de arquivos antes de enviar.
4. Abra um pull request explicando o que foi alterado e por quê.

## Mensagens de commit

Utilize mensagens curtas e objetivas, com um prefixo que indique o tipo de alteração:

- `docs: adiciona plano de implantação`
- `fix: corrige link do GitHub Pages`
- `feat: inclui novo projeto no portfólio`
- `chore: atualiza arquivos ignorados`

## Organização dos arquivos

- Preserve a numeração e os nomes das pastas principais.
- Use nomes de arquivos claros e padronizados.
- Mantenha materiais do Bootcamp I em `02_Disciplinas_Atuais/Bootcamp_I/`.
- Registre projetos e certificados em `03_Projetos_e_Certificados/`.
- Inclua documentos de implantação, segurança e decisões técnicas em `docs/`.
